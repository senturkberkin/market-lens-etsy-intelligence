# Market Lens

## Primary keyword workflow (in development)

The primary page now follows **type → see keyword measurements → choose a strategy**. It requests exact and related keywords from the Alura API and displays two provider fields: estimated monthly Etsy searches (Alura's average of the last 12 completed months) and competing listing count. The app does not calculate a third opportunity score, invent an exact match when the provider omits it, or ask the user to supply demand. Unknown values remain unknown. Each result names its source, retrieval time, method, and unknown geography. The previous research interface is preserved at `legacy.html`.

**Buyer pull:** Search counts alone do not establish purchases. An explicit **Check buyer activity** action searches one page of Alura product results, keeps up to three listings whose title or a tag contains every query token, and checks each listing's reviews dated within the last 90 days. Each result links to the Etsy listing and shows its dated review count. A review is purchase-linked evidence, but its date is not the sale date, many buyers never review, and an empty or uncollected sample does not prove zero sales. Alura's last-completed-month sales number is shown separately as an estimate, never an actual transaction count. The check uses at most 13 included Free-plan credits (10 for a product page with results and one for each of three review pages), and the server refuses non-Free plans or insufficient credits. No automatic top-up or paid call is supported. The buyer check has fixture and endpoint tests; a real response and independent validation against Etsy listings remain release gates.

Set `ALURA_API_KEY` server-side in the Vercel Preview environment. The page does not accept or expose this credential. Vercel Authentication protects Preview before API functions run, and the functions fail closed outside `VERCEL_ENV=preview` or on cross-origin requests. This requires users to open the Vercel Preview URL while signed in; the GitHub Pages copy cannot call this protected API. The former `ZETY_ACCESS_TOKEN` is no longer used by this branch and can be removed from Preview after verification. Before each keyword call, the server queries Alura's free `/usage` endpoint and refuses to continue unless the account is on the Free plan with at least two included API credits remaining. A complete search uses at most two credits: one for the exact keyword and one for a page of related terms. No paid plan, credit top-up, or automatic upgrade is supported. Run `npm test` before deployment. The local `preview-server.js` serves explicitly synthetic UI fixture values only.

**Release gate:** a live Free-plan lookup for `wedding planner` returned an exact row and 25 related rows, consuming two included credits. The response shape and adapter work; the browser workflow has only been checked with local fixtures. Alura's volume is a third-party estimate, not Etsy's measured search count. Compare a diverse sample of provider figures with Etsy Marketplace Insights before describing accuracy as validated. Verify the deployed API and browser workflow on a private preview before promoting this as a finished tool. Production remains disabled by the new API code until Vercel Authentication protects the production domain; obtain confirmation before changing that project setting. Alura's API terms permit private research for one's own Etsy business and prohibit offering its data to other people in an app without written agreement. Keep this endpoint private and verify the intended personal use against their terms before live use.

Etsy digital product research dashboard with an official Etsy Open API provider boundary. Live Etsy listing counts and observed prices are retrieved server-side; unsupported demand metrics remain unavailable rather than being estimated from unrelated signals.

## MVP architecture

- **Data model:** product hypotheses, market observations (source/timestamp/method/confidence), operating assumptions, and normalized score weights.
- **Calculation engine:** `dist/js/calculations.js` contains pure revenue, profit, percentile, scoring, and sensitivity functions, covered by `test/calculations.test.js`.
- **UI:** a static, responsive dashboard in `dist/`, with browser-local persistence and JSON/CSV export.
- **Live ingestion:** `api/etsy-keyword.js` proxies Etsy Open API v3 from a serverless runtime. Set `ETSY_API_KEY` there and point `dist/config.js` at that deployment. Never put the key in the static client or GitHub repository.

## Data limits

Etsy Open API supplies active-listing results and observed listing prices, but not Etsy marketplace keyword search volume. The keyword report accepts dated, sourced demand observations and a documented product-gap assessment. The evidence-based engine returns EXPLORE, VALIDATE or AVOID under the rules in [ALGORITHM.md](./ALGORITHM.md); it never estimates sales from favorites or listings. Financial calculators use user assumptions and demo fixtures.

Keyword discovery starts with one unrestricted seed. It extracts phrases from relevant physical and digital listing titles and tags, labels observed phrases separately from synonym-based hypotheses, groups them by buyer need, audience, and format intent, and lets the user investigate each candidate through the Etsy report. The report shows sampled listing types and links. When a broad query returns no digital listings, a separate, labelled digital search probe may add more directions; its results are not combined with the original query. Discovery frequency is only a count within the returned relevance-ranked sample; it does not measure demand. The existing EXPLORE/VALIDATE/AVOID engine assesses digital product hypotheses only, and its output does not decide physical product viability. See [ALGORITHM.md](./ALGORITHM.md) for evidence limits.

Investigating a keyword now proposes up to five digital-product hypotheses from at least two relevant sampled listings. Each proposal includes audience, problem, format, core function, a tentative difference, the observed comparison, and links to sampled listings. Selecting one pre-fills the existing assessment form but never verifies its gap. If no relevant evidence exists, the report says that no evidence-linked concept is available. The application is static HTML/JS under `dist/`; there is no separate build step.
